======netboot.xyz======
[[https://netboot.xyz|netboot.xyz]] turns a node into a PXE network boot server. Machines on the LAN boot into a menu with installers, live systems and tools for dozens of operating systems — Debian, Ubuntu, Fedora, Rocky, Alma, Arch, Windows PE, Clonezilla, GParted, memtest and more. **Everything is loaded from the internet on demand: no ISO files to download or upload.**

netboot.xyz is a community application from the [[ns8:tebbiworld_repository|tebbiworld]] repository. Documentation and source can be found on [[https://github.com/tebbiworld/ns8-netbootxyz|Github]]

=====What it does=====
  - A machine starts network boot (PXE). Your existing DHCP server assigns the address; the boot server and boot file come either from **proxyDHCP** on this node or from **DHCP options 66/67** on your router.
  - The machine loads the netboot.xyz iPXE binary from this node over TFTP.
  - netboot.xyz shows its menu and pulls kernels, initrds and images from the distributions' official mirrors over HTTP(S).

The module picks the right boot file per firmware (legacy BIOS, UEFI x86_64, UEFI ARM64, optionally the signed Secure Boot chain) and includes the netboot.xyz web app for customising the menus, protected by a login and Traefik.

=====Architecture=====
Two rootless containers from the pinned ''ghcr.io/netbootxyz/netbootxyz'' image, sharing the ''netbootxyz-config'' volume (boot files and menus):

^ Container ^ Network ^ Ports ^ Purpose ^
| ''netbootxyz-tftp'' | host | 69/udp, optionally 67/udp + 4011/udp | dnsmasq: TFTP and proxyDHCP |
| ''netbootxyz'' | private | ''127.0.0.1:<port>'' → 8080 | menu editor web app behind nginx basic auth, fronted by Traefik |

TFTP and proxyDHCP need the host network: TFTP transfers use ephemeral ports and proxyDHCP must see LAN broadcasts. NethServer lowers ''net.ipv4.ip_unprivileged_port_start'' to 23, so the rootless container can bind them; the module opens the ports in the node firewall (''node:fwadm''). The web app has no authentication of its own and is never published directly. Because the ports are fixed, **only one instance per node** is possible.

=====Installation=====
On the NethServer 8 cluster leader:

<code bash>
add-module ghcr.io/tebbiworld/netbootxyz:1.0.0 1
</code>

Configure it — the boot server address must be a **static** address of the node:

<code bash>
api-cli run module/netbootxyz1/configure-module --data '{
  "pxe_server_ip": "192.168.1.10",
  "proxy_dhcp": true,
  "uefi_boot_mode": "standard",
  "host": "pxe.example.org",
  "lets_encrypt": false,
  "http2https": true,
  "admin_user": "admin",
  "admin_password": "s3cret-Passw0rd",
  "ip_allowlist": ["192.168.1.0/24"]
}'
</code>

On first start the image downloads the boot files and menus of the current netboot.xyz release into the volume. Then network-boot any machine in the LAN.

=====Pointing clients at the boot server=====
====Option A: proxyDHCP (recommended)====
Enable //Answer PXE clients directly (proxyDHCP)//. Your router keeps assigning addresses with options 66/67 empty; this node only adds the boot information for machines that network boot, choosing the file per firmware (DHCP option 93):

^ Client ^ Boot file ^
| Legacy BIOS | ''netboot.xyz.kpxe'' |
| UEFI x86_64 | ''netboot.xyz.efi'' or, in Secure Boot mode, ''secureboot-x86_64/shimx64.efi'' |
| UEFI ARM64 | ''netboot.xyz-arm64.efi'' or ''secureboot-arm64/shimaa64.efi'' |

Clients that already run iPXE (Proxmox and QEMU virtual machines, many server NICs) get the boot file directly in the proxyDHCP offer. Do not run a second PXE server in the same network.

====Option B: DHCP options on the router====
Keep proxyDHCP off and set on your DHCP server option 66 (TFTP server) to the boot server address and option 67 (boot file) to ''netboot.xyz.efi'' for UEFI or ''netboot.xyz.kpxe'' for BIOS machines. Most routers send one file to every client, so mixed BIOS/UEFI networks work best with proxyDHCP. On a DrayTek Vigor: //LAN » General Setup » DHCP Server Option//, both as ASCII strings.

=====Settings=====

^ Setting ^ Description ^
| Boot server address | Node IPv4 address the clients load the boot files from. Use a static address — a changed DHCP lease silently breaks network boot. |
| Answer PXE clients directly (proxyDHCP) | Adds the boot information next to the existing DHCP server. |
| UEFI boot mode | //Standard//: netboot.xyz iPXE binary (Secure Boot must be off on the clients). //Secure Boot compatible//: Microsoft-signed shim and iPXE-signed binaries; menus are loaded from ''boot.netboot.xyz''; the firmware must trust the Microsoft 3rd-party UEFI CA. |
| Host name | Host name of the menu editor web app; empty disables the web route. |
| Let's Encrypt / HTTP to HTTPS | TLS for the web app. |
| Login / password | HTTP basic auth of the web app (blank password keeps the stored one). |
| Allowed client networks | CIDR list allowed to reach the web app; empty allows all. |

====Where the menus come from====
Once netboot.xyz runs, it looks for local menus on the TFTP server your DHCP server announced (''next-server''). If the router announces none, the menus come from ''boot.netboot.xyz'' over HTTPS; if it announces itself, netboot.xyz tries there first and falls back after a few timeouts — press ''p'' at the "DHCP proxy detected" prompt to use this node. The operating system images always come from the internet; local menus only matter if you customise them in the web app.

=====Limitations=====
  * One instance per node (fixed TFTP/proxyDHCP ports in the host network).
  * Boot images are always loaded from the internet; clients need internet access. The web app can mirror assets, but the module does not publish them over HTTP.
  * IPv4 only.

=====Backup=====
The NS8 backup includes the web app login and the ''netbootxyz-config'' volume (boot files and customised menus).
